Reading a prompt-adherence test without fooling yourself

2026-11-26 · working notes

Prompt adherence tests are easy to rig by accident. If the prompt says a red jacket and the output shows a red jacket, that proves very little, because red jackets are common in training data. The test only means something when the prompt contains a relationship: the jacket is wet, the jacket is two sizes too large, the jacket is the only red object in a grey street.

Build a small set of relational prompts and keep them fixed across models. Score each output on whether the relationship survived, not on whether the image is attractive. A model that produces an ugly but correct frame is more useful than one that produces a beautiful frame that ignored the instruction, because you can fix ugly with lighting and you cannot fix ignored with anything. Check negatives separately. Most tools handle "no text" and "no extra fingers" badly, and their failure mode is quiet: the frame looks fine until you notice the sign in the background. Test one negative per run so you know which one broke.

Keep a written log with the prompt, the seed and a one-line verdict. After twenty runs the log tells you more about a model than any leaderboard, because it reflects the shots you actually need rather than the shots a benchmark chose.

One more habit: rerun the same prompt after a week. Providers swap checkpoints quietly, and a prompt that worked in October can fail in November with no announcement. A dated log catches that before a client does.
